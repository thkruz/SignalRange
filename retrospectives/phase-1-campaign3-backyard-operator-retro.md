# Phase 1 — Campaign 3 (Backyard Operator) Foundations Retro

## What worked

- **Opt-in-field gating held up across six different seams.** `gainModel: 'fixed'` (antenna), `isDirectSampling` (LNB), `circularHandedness` + `circularCrossPolLoss_dB` (polarization), `isAfcEnabled` (receiver), `stationClass: 'backyard'` (tab set), and circular OMT mode all default to legacy behavior when absent. Full suite (4549 tests) and type-check stayed green throughout with only intentional test updates (band whitelist gained VHF/UHF).
- **The TLE-authoring script as a checked-in tool** (`scripts/author-tle.mjs`, closing the C2 retro action item) produced all three birds in one run: WXSAT-19 AOS T+3.0/max el 55°, CUBEHOP-1 AOS T+18.0, NAVSTAR-77 at el 89° from T+0. Unit tests assert the same numbers, so propagation regressions break CI.
- **Live browser verification caught what unit tests never would have** (see below). The Playwright probe pattern — load scenario, hold-to-skip dialogs, ride the pass on the sim clock, read the SDR console readouts — confirmed AOS at exactly T+3:00 with C/N 16.5 dB, LOCKED, and +3.0 kHz Doppler on the waterfall, precisely matching the authored physics.
- **The SDR Console as a campaign-gated tab over headless cores** (not a UI-variant fork) meant every existing objective condition type worked unchanged, and the freeware styling lives entirely inside the tab + one `body.campaign-ham-sdr` CSS block.
- **User feedback tightened the tab set immediately:** the first cut kept Dashboard/ACU/RX Analysis/GPS Timing alongside the SDR Console, which broke the fiction (a fence-post QFH has no ACU) and duplicated function. Backyard stations now show only SDR Console + Observations; every Dashboard card deep-linked to a removed tab anyway. Rotator control moved into the SDR Console as a Gpredict/rotctl-style panel (AZ/EL readout, satellite select, TRACK toggle → program-track; fixed mounts show "FIXED MOUNT — NO ROTATOR"). Order gotcha: `handleTrackingModeChange` clears `targetSatelliteId`, so engage mode first, then set the target.

## What didn't

- **The ±1° reception box almost sank the whole campaign concept.** `antenna-core.ts` `get rxSignals()` only fed the antenna satellites within a planar ±1° az/el box of boresight — invisible for pencil-beam dishes, fatal for a 140°-HPBW QFH staring at zenith (first live pass: zero carrier). Fixed with a fixed-gain-only branch: true great-circle angular separation accepted out to one HPBW. The same planar `hypot(dAz, dEl)` bug lived in `applyPropagationEffects_` off-axis math (badly wrong near zenith); also branch-fixed. The step-track retro had literally warned about "±1° reception cliffs" — worth grepping for remembered failure modes before designing, not after.
- **The filter bank silently drives a decode gate.** `getVisibleSignals()` (which feeds every decode/feed surface) rejects signals below `filterModule.state.noiseFloor + totalRxGain`, and the filter *recomputes* `noiseFloor` from `bandwidthIndex` every update — the explicit `noiseFloor` in station config is dead weight. Backyard signals run ~15 dB colder at the AGC output than teleport chains, so the copied 40 MHz Galway filter ate the feed while the modem happily reported LOCKED. Fix was physical and pleasing: give narrowband downlinks narrowband filters (200 kHz for VHF/UHF — index 6, whose 3.0 dB insertion loss also stays under the permanent-alarm threshold that 100 kHz tripped — and 5 MHz for GPS L1). Decode verified live to engage right at AOS.
- **Debugging by armchair unit analysis failed twice** (wrong gate theory both times); one temporary `console.log` in the decode path + probe console capture found it in a single run. Instrument earlier.
- **Placeholder assets:** APT/SSTV decode payoffs reuse `blue-1.mp4`/`blue-2.mp4`, the campaign card reuses the NATS image, and Riley has no portrait or audio yet (enum fallbacks handle it gracefully). Real weather-image/SSTV assets belong in R2 before the campaign ships.

## What to change next time

- **The modem-bandwidth rule needed to explain itself.** User testing surfaced that lock only works when the channel BW brackets the signal (signal must fit AND fill ≥40% of the channel — receiver.ts's FEC fill rule), but the console gave dead readouts outside that window even with a carrier blazing on the waterfall. Fixed UI-side without touching shared physics: the S-meter now shows passband energy straight from the spectrum bins when the demodulator has no carrier, and the lock indicator diagnoses itself (LOCKED / BW TOO WIDE / BW TOO NARROW / MODE?). Verified by live sweep: 34–80 kHz locks and decodes the 34 kHz APT signal; outside that, the hint says which way to go. Lesson: when a sim rule is realistic but non-obvious, the instrument should show the *why*, not just the failure.
- **The spectrum analyzer misrendered every wideband signal (pre-existing, all campaigns).** `getInputSignals()` clamped each displayed signal's bandwidth to the RBW — a 2 MHz GPS hump at 30 kHz RBW drew as a 30 kHz needle, Galway's 36 MHz video at 1 MHz RBW as a 1 MHz spike, and the 34 kHz APT block as a hairline. User feedback ("BW too narrow despite visually looking well wide of the margins") exposed it: the receiver judged against the true 2 MHz signal while the display lied. Fixed by removing the clamp and adding the matching PSD correction in `spectrum-data-processor.ts` (wideband signals draw at per-RBW-bin power, so the GPS hump now sits a few dB above the noise — exactly the spread-spectrum teaching visual). Display-only change; no physics or objectives touched. The console also gained spectrum dB-axis labels and a full-height layout, and the BW-TOO-NARROW hint switched from max-bin to mean-bin passband excess so PSD-flattened humps still trigger it.
- **Consider adding audio demodulation.** After benchmarking against SDR++, the SDR Console gained the spectrum trace, VFO passband overlay, digit-wise tuning, bookmarks, band plan ribbon, mode/FEC/bandwidth controls, and an RF gain slider with real ADC clipping/quantization consequences (AGC bypassed on backyard rigs). The one defining SDR feature still missing is *hearing* the passband — FM audio, APT tick-tock, CW beacons. The sim has no audio path from the signal model today (the console's Recorder section is a stub); squelch/de-emphasis/stereo controls only make sense once that exists. Worth scoping as its own phase.

- **Verify the yagi leg live.** The probe validated the QFH pass end-to-end; the CUBEHOP-1 leg (program-track on the yagi, handedness swing, Doppler chase T+18→T+30, AFC) is unit-tested but not yet driven in-browser — it needs a ~25-minute session or a sim-time acceleration hook. An `e2e-scenario-test` for `ham-sdr-sandbox` is the natural next artifact.
- **Waterfall amplitude range needs a calibration pass.** The noise floor renders mid-scale light blue on the backyard spectrum analyzers (`minAmplitude: -110/-50` copied from Galway); darker noise would make the SDR look more like SDR#. Cosmetic, config-only.
- **`objectives element not found` in the probe** — the objectives panel selector guess was wrong; find the real container class for future probes (objective completion itself was confirmed via the checkpoint-save event firing).
- **The dead `noiseFloor`/`bandwidth`/`insertionLoss` fields in filter config** (overwritten from `bandwidthIndex`) are a foot-gun exactly like the C2 `antennas: []` array — worth a cleanup that derives config from the index alone.
- Scenario 1+ of the campaign should force the handedness decision explicitly (start the yagi on LHCP) and stage the AFC discovery (manual chase first pass, AFC second pass) — the sandbox proves the mechanics; the scenarios should teach them.
